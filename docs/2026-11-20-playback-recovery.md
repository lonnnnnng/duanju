# 播放空响应修复（2026-11-20）

线上 v0.2.19 在《公路求生榜一说她要走到公路尽头第三季》《0174号奖券》播放时，
App 取流返回 HTTP 200、正文 0 字节；网页回退提示仅提供受保护播放，最终播放接口返回 502。

## 复现与原因

- 服务、分集列表和 FFmpeg 正常，错误发生在获取媒体地址之前。
- 同一服务器使用主设备、现有辅助设备及新注册设备访问
  `/novel/player/multi_video_model/player/v1/`，都复现空正文。
- 对照参考项目 JavaScript 签名、切换 a/b 域名、去掉末尾斜杠、使用 HTTP/1.1，均未恢复原请求。
- 保持 7.4.3.32 播放参数、V5 签名、设备和请求体，改用
  `/novel/player/multi_video_model/v1/` 后得到正常业务响应和 1080p 媒体。
  该入口仅用旧版签名仍返回空正文，不能直接回滚到旧实现。
- 设备重试还存在独立问题：只排除上一次失败设备，两个辅助设备会循环 A → B → A。

这些证据说明现有播放请求在主入口被返回空正文，可用的 App 批量入口能恢复取流。
上游没有给出拒绝原因，无法仅凭此确定其内部策略。

## 修改

1. 主入口空正文立即尝试 App 批量入口；两者共用 V5 签名、分集 ID、完整清晰度参数和媒体解析。
2. 两个入口仍失败时才轮换辅助设备，按本次请求已失败设备集合排除重复尝试，最多轮换三次。
   在锁内返回选定设备身份，避免并发请求覆盖轮换结果。
3. 签名移到限流队列放行后生成；签名准备失败时释放并发名额，不发送未签名请求。
4. 区分空正文、超大响应、业务错误与非法 JSON，记录入口回退日志，保留取消及 403/429 限流行为。

未重新引入最高 720p 的站点 `play-info`，下载清晰度选择与合并校验维持原逻辑。

- 每集开头和中段各解码 3 秒，均有音频和视频；两部剧首集完整下载并验证 HEVC + AAC。
- Chromium 桌面 1280×900 与手机模拟 390×844 下，两部剧均通过真实播放、持续出画和关闭播放器验证。
- 使用独立临时数据目录测试，不修改线上设备池、配置、下载任务或媒体文件。
- 回归测试覆盖入口回退、完整清晰度、第三台设备、新设备注册、有限重试、取消、错误分类和排队后签名。
