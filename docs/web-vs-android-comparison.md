# Web 端与 Android 端实现对比

对照两份实现：Web（Go 服务端 + 浏览器前端）与 Android（原生 App 直连）。接口与实现细节见 [remote-apis-and-implementation.md](remote-apis-and-implementation.md)。

---

## 一、结论速览

| 维度 | Web 端 | Android 端 |
| --- | --- | --- |
| 架构 | 浏览器 → 自建 Go 服务 → 红果上游 | App → 红果开放接口（无自建服务） |
| 请求签名 | 需要（新旧两套 X-Gorgon / X-Argus / X-Ladon） | 不需要（只用开放 GET 接口） |
| 上游接口族 | `sinfonlineb` + 官网 + 第三方 | `sinfonlinec`（开放） |
| 播放管线 | 服务端按能力 remux/转码，fMP4 流式 / HLS | 整集下载 + 本地 ffmpeg 解密 + 本地 mp4 |
| 首播等待 | 秒级（流式起播） | 整集下载耗时（约等于该集码率 × 时长） |
| 下载功能 | 完整（队列、清晰度、重试、合并、校验、磁盘守护） | 无（只有播放缓存） |
| 缓存 | 服务端磁盘 + 内存，多级 | 内存 LRU + 封面磁盘缓存 + 播放 mp4 |
| 失效影响 | 上游签名/页面变化，改服务端即可 | 上游开放接口变化，必须发新版 App |
| 部署 | 需服务器与 ffmpeg | 安装即用，零运维 |
| 代码规模 | 服务端约 3.9 万行（含大量测试）+ 前端 6 千行 | 约 20 个 Kotlin 文件 + 2 个 core 文件 |

## 二、架构对比

### Web

```
浏览器 ──同源 HTTP──> Go 服务
                       ├─ provider_*.go   上游适配（签名、解析、回退）
                       ├─ ui_*.go         业务接口、任务、播放会话
                       ├─ playback_*.go   ffmpeg 出流、HLS 代理
                       └─ data/           剧库、下载、历史、缓存
```

- 所有上游细节封装在服务端，浏览器只处理业务 JSON。
- 服务端承担 CPU 密集任务（转码/解密/合并），对硬件有要求。
- 支持局域网多设备访问、Emby 导出、自更新。

### Android

```
MainActivity / Fragments
   └─ DirectClient（唯一上游客户端）
        ├─ homeTab / searchHomeItems / seriesDetail / media
        ├─ HongguoSign.contentKey（仅密钥派生）
        └─ FFmpegKitNext（解密落盘）
   └─ Media3 ExoPlayer（播放本地文件）
```

- 无服务端，请求与解析全部在手机上完成。
- 依赖 `sinfonlinec` 开放接口，绕过了签名，但接口能力受限于该族。
- 复杂逻辑集中在 `DirectClient.kt`（约 700 行），UI 层薄。

## 三、逐功能对比

### 3.1 首页

| 项 | Web | Android |
| --- | --- | --- |
| 主接口 | `POST landpage/v/`（签名） | `GET bookmall/tab/v/`（开放） |
| 分类维度 | `short_play` / `comic_series` / `ai_series` | `tab_type=8` 单一短剧 tab |
| 分页 | `offset` + `session_id`，服务端持久化游标，可增量/续抓 | `offset` + `session_id`，`next_offset > offset` 判定 |
| 筛选 | 服务端透传 | 两级面板，`outer_row` + `inner_rows` |
| 推荐 | `/api/ui/recommendations`，`filter_ids` 去重 | 无独立推荐流（首页即推荐） |
| 榜单 | 官网 `/rank/*` SSR 解析，4 个榜单 | 无榜单页，仅首页 `recommend_info.rank` 显示名次 |
| 回退 | 官网分类页 SSR | 无 |
| 数据落盘 | 有（剧库 + 游标） | 无（仅内存/封面缓存） |

> 差异根源：开放接口 `bookmall/tab` 本身自带推荐+筛选+榜单名次，Android 不需要另建推荐流；Web 端为了更细的分类与榜单，使用了 App 目录接口与官网页面。

### 3.2 搜索

| 项 | Web | Android |
| --- | --- | --- |
| 接口 | `hongguoduanju.com/api/search/result` | `fetch-debug/v/` |
| 响应体积 | 中等（结果列表 JSON） | 5–6 MB，`debug_info` 占绝大部分 |
| 解析 | 直接 JSON 解码 | 流式读取 + 括号配对截断 `data` |
| 封面 | 官网结果自带 | 结果无封面，逐条补详情（8 线程） |
| 缓存 | 5 分钟 / 64 关键词 | 无 |
| 并发合并 | 有（single-flight） | 无（UI 层防重复点击） |
| 失败处理 | 明确错误文案 | 重试 3 次，失败抛错 |

> Android 的搜索是「先拿 ID，再补详情」，请求数 = 1 + N；Web 一次拿全。代价是 Android 搜索耗时更长、流量更大，但接口更稳定（无签名）。

### 3.3 详情

| 项 | Web | Android |
| --- | --- | --- |
| 主接口 | `video_detail/v1/`（签名） | `multi_video_detail/v/`（开放） |
| 回退 | 官网 `/detail?series_id=` SSR | 无 |
| 校验 | 严格（ID 一致、集号连续、数量匹配） | 宽松（有 `vid` 即可） |
| 缓存 | 5 分钟 / 128 条，single-flight | 无（每次进入详情重新请求） |
| 集数排序 | 按 `vid_index` | 按 `vid_index` |
| 选集分组 | 前端 30 集一组 | 前端 30 集一组 |

### 3.4 播放

| 项 | Web | Android |
| --- | --- | --- |
| 取流主路 | App 模型接口（新版签名） | `multi_video_model/v/`（开放，`version_code=74232`） |
| 回退 | 网页 `protected/play-info` → 第三方 `djapi` | **无** |
| 密钥 | 服务端派生 | 本地派生 |
| 解密 | 服务端 ffmpeg | 本地 ffmpeg-kit |
| 输出 | 服务端 remux/转码，fMP4 流式或 HLS | 整集 mp4 落盘后播放 |
| 起播时间 | 低（边转边播） | 高（等待整集下载） |
| 流量 | 只传实际观看部分（HLS/fMP4 可中断） | 每集完整下载一次 |
| 弱网 | 服务端代理重试、可切清晰度 | ffmpeg 失败即报错（注释声称的 Java 回退未实现） |
| 音视频分离 | 支持（DASH 音轨独立） | 只取 `main_url`，不支持分离音轨 |
| H.266 | 服务端可转码 | 直接拒绝 |
| 断点续播 | 服务端会话 + 历史 | 播放器内 `pendingSeekMs` |
| 清晰度切换 | 支持（重开 plan） | 只取最高清晰度 |

> 这是两端最大的体验差异：Web 是「流媒体服务端」，Android 是「先下载后播放」。

### 3.5 下载

| 项 | Web | Android |
| --- | --- | --- |
| 用户下载 | 支持 | 不支持 |
| 入口 | 剧库勾选 → `/api/ui/download` | — |
| 队列 | 持久化任务，暂停/恢复/取消/重试/优先级 | — |
| 清晰度 | 360/480/720 可选 | 仅播放用的最高清晰度 |
| 落盘 | ffmpeg `-c copy` → `.part.mp4` → 原子重命名 | 同上，但仅到 App 缓存 |
| 校验 | 下载前 probe、下载后校验任务 | 无 |
| 磁盘保护 | 有（空间守护 + 预留） | 无 |
| 合并 | 合集自动/手动合并 + 校验文件 | 无 |
| 输出位置 | 配置的 `downloads/`，可被 Emby 读取 | App 私有缓存 |

## 四、协议与安全对比

| 项 | Web | Android |
| --- | --- | --- |
| 上游域名 | `sinfonlineb`（App 接口）、`hongguoduanju.com`（官网）、`djapi`（备用） | `sinfonlinec`（开放接口） |
| 请求方法 | POST（App 接口）+ GET（官网/备用） | 全部 GET |
| 签名 | 旧版（目录/详情）+ 新版（播放模型） | 无 |
| `version_code` | 固定 73532 | 65532（浏览）/ 74232（取流） |
| 设备身份 | 服务端随机并持久化 | App 随机并持久化 |
| 内容密钥 | 服务端派生，不落日志 | App 本地派生，不落日志 |
| 密钥暴露面 | 浏览器不接触密钥；服务端持有 | 密钥在进程内存与 ffmpeg 参数中出现 |
| Referer/Cookie | 官网接口需要 | 不需要 |

## 五、稳定性与失效面

| 场景 | Web | Android |
| --- | --- | --- |
| 签名算法变更 | 需更新服务端并重启，用户无感 | 不受影响（无签名） |
| 开放接口收紧 | 无影响（不用） | 必须发新版 App，老版本立即失效 |
| 官网改版 | 搜索/榜单/回退路径失效，主路径仍可用 | 不受影响 |
| 播放模型接口空响应 | 自动回退网页/第三方 | 播放失败 |
| 第三方接口失效 | 只影响最后一级回退 | 不使用 |
| 上游限流 | 全局限速 + 重试 | 无统一限速，可能触发风控 |
| 客户端版本碎片 | 无（浏览器始终最新） | 有（用户不升级则一直用旧逻辑） |

## 六、性能与资源

| 项 | Web | Android |
| --- | --- | --- |
| 首屏 | 依赖服务端剧库缓存，通常秒开 | 直连接口，1–3s（视网络） |
| 搜索 | 单请求 | 1 + N 请求，N≈20 |
| 详情 | 缓存命中快 | 每次现拉 |
| 播放起播 | 1–3s（remux）或直连重定向 | 10s–60s（整集下载） |
| CPU | 服务端转码时较高 | 手机解密时中等 |
| 内存 | 服务端常驻 + 缓存 | 封面 LRU + ExoPlayer 缓冲 |
| 流量 | 按观看进度 | 每集完整下载 |

## 七、运维与迭代

| 项 | Web | Android |
| --- | --- | --- |
| 部署 | 需服务器、ffmpeg、磁盘 | 无 |
| 更新 | 服务端热更新（`/api/ui/update` 或流水线） | 需重新安装 APK |
| 灰度/回滚 | 服务端可快速回滚 | 只能发旧版本 |
| 多端支持 | 任意浏览器/电视 | 仅 Android |
| 调试 | 服务端日志完整 | 依赖 logcat |
| 数据 | 剧库/下载/历史在服务器 | 剧库无持久化，历史/设置在本地 |

## 八、取舍与建议

**Web 端优势**

- 播放体验好：流式、可转码、可切清晰度、支持音视频分离与 H.266 转码。
- 功能完整：下载队列、合并、Emby、榜单、推荐、多用户历史。
- 失效修复快：签名或页面变化只需改服务端。

**Web 端代价**

- 需要服务器与 ffmpeg，转码吃 CPU。
- 签名逻辑复杂、易随上游变化。
- 依赖第三方备用接口，存在外部风险。

**Android 端优势**

- 零服务器、零运维，安装即用。
- 不走签名，规避了签名失效问题。
- 代码集中、易审计（`DirectClient.kt` + `HongguoSign.kt`）。

**Android 端代价**

- 无回退，开放接口一旦变化只能发版。
- 整集下载后播放，首播慢、流量大、不能切清晰度。
- 无用户下载、无榜单/推荐流、无音视频分离支持。

**演进建议**

1. Android 增加取流回退：至少接入官网 `protected/play-info`，避免单点失败。
2. Android 改为边下边播（本地 HLS 代理或 `Media3` 自定义 `DataSource` 解密），把首播从「整集」降到「首片」。
3. 统一接口抽象：把 Web 端的三级取流与解析规则抽成共享规格（文档 + 向量测试），避免两端再次漂移。
4. Web 端把搜索/榜单/详情回退路径纳入监控，官网改版时能第一时间发现。
5. 版本号与发布已统一（同一 Release 含 APK 与服务端），后续保持 `versionName` 与 `vX.Y.Z` 同步。
